# AI Gateway Design & Architecture

> **Note:** This is a forward-looking design document. The AI Gateway is not yet implemented.

## Overview
The AI Gateway is the centralized entry point for all conversational workflows in NexusOps. It orchestrates communication between the React UI, the underlying Language Models (LLMs), and the deterministic backend Tool Manager. 

## 1. Authentication & Authorization
- **Authentication**: The Gateway uses the exact same `auth.js` middleware as standard API routes. The user must provide a valid JWT.
- **Authorization**: The Gateway itself only requires the `ai.access` feature flag/permission. However, when the Orchestrator invokes a tool, the Tool Manager dynamically enforces the specific RBAC requirement for that tool (e.g., `payroll.run`).

## 2. Orchestration & Context Loading
1. **Request Intake**: `POST /api/v1/ai/chat` receives the natural language prompt.
2. **Memory Manager**: Fetches previous conversation turns from Redis. Trims and summarizes context to fit the model's context window.
3. **Prompt Builder**: Assembles the System Prompt, injecting:
   - User identity and permissions (so the AI knows what it is allowed to do).
   - Available tools from the Tool Manager (MCP integration).
   - The user's query and trimmed history.

## 3. Provider Abstraction & Model Routing
The `ProviderRouter` abstracts the specific LLM being used (Gemini, Groq, OpenRouter).
- It allows dynamically routing simple classification tasks to faster, cheaper models (e.g., Groq Llama 3) while routing complex reasoning to frontier models (e.g., Gemini 1.5 Pro).
- It implements fallback strategies in case a provider experiences an outage.

## 4. Tool Execution & Validation
The LLM does not execute code. It returns a JSON schema indicating a tool call.
1. The Orchestrator forwards this payload to the `ToolManager`.
2. The `ToolManager` validates the payload against strict Zod schemas.
3. It checks the user's RBAC permissions.
4. It invokes the exact same Service layer methods used by the React UI.
5. It returns the structured JSON result to the Orchestrator.

## 5. Token Accounting, Cost & Billing
The Gateway intercepts all payloads returned by the Provider Router.
- It calculates `inputTokens`, `outputTokens`, and `latencyMs`.
- It derives `costUsd` based on the active provider's pricing tier.
- It logs these metrics to the `ai_usage` collection for tenant-level billing.

## 6. Streaming & UX
To maintain a snappy user experience, the Orchestrator supports Server-Sent Events (SSE). While tools execute synchronously, the narrative response generated by the LLM post-execution is piped directly to the client chunk-by-chunk.

## 7. Security, Logging & Audit
- **Dedicated Audit Log**: Every prompt, tool execution, and response is logged to `ai_audit_logs`. This prevents prompt-injection obfuscation and provides a clear paper trail of AI decisions.
- **Data Privacy**: PII is scrubbed or encrypted before being sent to external providers, strictly adhering to enterprise data agreements.
